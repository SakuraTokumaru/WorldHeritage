# ログイン・新規登録ページ（担当：王）

IDM世界遺産部サイトのログイン機能です。アカウントは **Supabase**（クラウドのデータベース）に保存されるので、サーバーを自分で用意しなくても、誰のパソコンからでも同じアカウントでログインできます。

## 開き方

どれでも動きます。

1. **ファイルをダブルクリック**：`login.html` または `signup.html` をブラウザで開く
2. **ローカルサーバー（おすすめ）**：このフォルダでターミナルを開き、
   ```
   python3 -m http.server 8000
   ```
   を実行して、ブラウザで `http://localhost:8000/login.html` を開く
3. **GitHub Pages**：リポジトリの Settings → Pages で公開すると、URL を知っている人なら誰でも開けます

※ インターネット接続が必要です（Supabase と Google Fonts を読み込むため）。

## ファイル一覧

| ファイル | 内容 |
|---|---|
| `login.html` | ログインページ（メールアドレス＋パスワード） |
| `signup.html` | 新規登録ページ（ユーザー名・メールアドレス・パスワード・確認用） |
| `auth.js` | 登録・ログイン・ログアウトの処理、入力チェック、エラーメッセージ |
| `auth.css` | ログイン／新規登録ページのデザイン（トップページの配色に合わせています） |
| `auth-status.css` | トップページのヘッダーに出す「ログイン」／「〇〇 さん・ログアウト」の見た目 |
| `supabase-config.js` | Supabase の接続先（URL と anon キー） |
| `schema.sql` | データベースのテーブル定義（Supabase に実行済み。参考用） |

## トップページ（main.html）との連携

`main.html` には次の2か所だけ追加しています。

- `<head>` 内：`auth-status.css`・Supabase・`supabase-config.js`・`auth.js` の読み込み
- ヘッダーの `head-tag` 内：`<div id="auth-status"></div>`

この `div` の中に、ログインしていなければ「ログイン」ボタン、ログイン中なら「〇〇 さん」と「ログアウト」ボタンが自動で表示されます。**ヘッダー担当の人へ**：位置や見た目は自由に動かして大丈夫ですが、`id="auth-status"` だけは残してください。

## 使い方

1. `signup.html` で新規登録 → 自動でログインされ、トップページへ移動
2. 次回からは `login.html` でメールアドレスとパスワードを入力
3. ログイン中に `login.html` / `signup.html` を開くと「〇〇 さんとしてログイン中です」と表示されます（ログアウトもここからできます）

- 確認メールは送られません（デモ用に Supabase 側でメール確認をオフにしています）
- パスワードは 8 文字以上、ユーザー名は 2〜20 文字。同じユーザー名・メールアドレスは登録できません

## データベースのしくみ

- メールアドレスとパスワードは Supabase の `auth.users` に保存されます。パスワードは**ハッシュ化**されるので、管理者でも元のパスワードは見られません
- ユーザー名などは `profiles` テーブルに保存されます（登録時にトリガーで自動作成）

  | 列 | 型 | 内容 |
  |---|---|---|
  | `id` | uuid | `auth.users` の id（主キー・外部キー） |
  | `username` | text | ユーザー名（大文字小文字を区別せず重複禁止） |
  | `role` | text | `member` または `admin` |
  | `created_at` | timestamptz | 登録日時 |

- **行レベルセキュリティ（RLS）**により、各ユーザーは自分の行しか読めません
- 登録されたユーザーは Supabase ダッシュボードの **Authentication → Users** と **Table Editor → profiles** で確認できます

## 注意

- `supabase-config.js` に書いてある **anon キーは公開してよいキー**です（RLS で守られているため）。GitHub に上げても問題ありません
- **`service_role`（secret）キーは絶対にファイルに書かない・GitHub に上げないでください**（データベースの全権限を持つキーです）
- `auth.js` などを修正してもブラウザに反映されないときは **⌘⇧R（Windows は Ctrl+Shift+R）** で再読み込みしてください
